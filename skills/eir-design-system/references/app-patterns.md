# App Patterns

Use this file when the task is a product UI instead of a static mock.

## Page Formula

1. Strong top navigation with a compact brand lockup
2. Hero or command surface with one dominant action
3. Proof layer: stats, trust markers, or featured objects
4. Main working area: cards, filters, results, form, or conversation
5. Focused footer with repo or documentation paths

## Cards

- Rounded but not bubbly
- Warm surface, subtle border, soft shadow
- Use one accent strip, glow, or orb if emphasis is needed
- Metadata should be calm and compact

## Forms

- Group fields into meaningful sections
- Pair a live preview or helper panel with the form when possible
- Make primary action visually obvious
- Focus state should use teal ring, never browser default

## Landing Pages

- One dramatic atmospheric background is enough
- Use asymmetry: large headline block plus a dense supporting panel
- Bring in the Eir Aura through orbs, cards, or logo moments
- Avoid generic startup gradients and glass overload

## Dashboards and Registries

- Keep filters in a dedicated control surface
- Use cards that communicate trust, status, and recency quickly
- Show the object title first, then owner/path, then operational metadata
- Make external repo and internal detail actions equally easy to reach
